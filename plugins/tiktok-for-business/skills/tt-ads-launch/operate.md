# 运营分支：已经在投的广告出了问题，或想加量

到这个分支才读这个文件。进入条件二选一：他开场说的就是在跑广告的事（掉量、成本涨、不消耗、想加量、被拒、什么时候能切），或阶段 3 查到这类广告已经在跑。进入后不走首投的阶段 2 到 8，走下面四步，每步一条消息。

## 第 1 步 读报表

先说一句要看什么："我去看三样：近 7 天和 30 天的消耗和成本、素材表现、审核和余额。"再调工具，只调这一步要用的：

| 看什么 | 工具 | 用来判断 |
|---|---|---|
| 近 7 天对近 30 天：消耗、结果数、CPA 或 ROAS、CTR、CPM、频次，按广告组 | report_integrated_get；Shop 用 gmv_max_report_get | 掉的是量还是成本，从哪天开始 |
| 各素材的 CTR、消耗占比、投放天数 | creative_report_get、report_video_performance_get | 素材疲劳 |
| 审核状态 | adgroup_review_info_get、ad_review_info_get | 被拒或审核中 |
| 余额、账户状态 | advertiser_info_get | 不消耗的第一原因 |
| 行业基准 | report_ad_benchmark_get | CPM、CTR 是贵还是正常 |
| 受众规模 | ad_audience_size_estimate | 人群太窄 |
| 平台诊断 | 先 tool_diagnosis_get，再 tiktok_ads_diagnosis_agent，用法见下 | 平台自己给的原因和建议，当作证据之一，和报表数据一起定首因 |

他说"ROAS 掉了"但没说哪个广告：先 campaign_get 列在跑的，超过 3 个让他指一个，不替他猜。

**两个平台诊断工具怎么用**（报表拉完就调，和报表一起看，不单独成一步）：

1. **tool_diagnosis_get**：结构化的问题清单，便宜，先调。传 advertiser_id 和他指的广告组 adgroup_ids（最多 20 个），issue_category 按他的抱怨选：成本涨或掉量传 CREATIVE 和 BID_AND_BUDGET；有点击没结果传 EVENT_TRACK；不消耗三类都传。只返回有问题的广告组；返回空不等于没问题，只是平台没检出。
2. **tiktok_ads_diagnosis_agent**：平台的诊断对话，给原因和建议，支持追问。传法：ctx.advertiser_id 必填；campaign_id 或 adgroup_id 传他指的那个（账户级诊断才不传）；issue_type 按他的话映射：不消耗、没曝光 → NO_SPENDING，消耗降、预算花不完 → LOW_SPENDING，成本涨、CPA 高 → HIGH_CPA，CTR 掉、素材跑太久 → CREATIVE_FATIGUE，说不清 → UNCLEAR_DIAGNOSIS；issue_date 他说了日期就传，没说不传；messages 里放他的原话一句。session_id 自己生成一个 32 位以内的字符串，这次诊断的所有追问（他问"为什么""换上周看看""看另一个广告组"）都复用同一个，换一个不相关的话题才换新的。
3. 边界：diagnosis_agent 不支持 GMV Max，Shop 卖家的诊断只用 gmv_max_report_get 加卡 1 的首因顺序；两个工具都只看在投的广告组，暂停的看不到。
4. 怎么用结果：平台给的原因进诊断卡的"最可能的原因"候选，和你从报表推的首因对一下。一致就直接用；不一致，按报表数据能证实的那个定首因，另一个写进"排除了什么"或"还可能是"，不替平台背书也不无视它。平台给的建议动作同样要过第 3 步的规则（一次一个变量、花钱先确认），不照单执行。

## 第 2 步 诊断卡

一张表，给用户看：

| | |
|---|---|
| 现象 | 用他的话加数据："近 7 天 ROAS 1.9，前 30 天 2.8；消耗没降" |
| 最可能的原因 | 只给一个首因，一句为什么它排第一 |
| 排除了什么 | 一行，列查过但没问题的：余额够、审核通过、事件回传正常 |
| 建议动作 | 一个动作，改什么、改多少 |
| 什么时候看结果 | 预算 2 天，素材 3 到 5 天，出价或目标 7 天 |

首因按下面的顺序查，第一个对上的就是首因，不并列：

**不消耗，或开启后 72 小时消耗不到日预算 20%**
1. 余额 0 或账户不可用
2. 审核未通过或被拒
3. 没开：campaign、广告组、ad 任一层是 DISABLE，或广告组下没有 ad
4. 出价或目标回报定太高（ROAS 目标高于推荐值、Cost Cap 低于历史成本）
5. 预算低于平台下限，或日预算太小攒不出学习
6. 受众太窄（受众规模估算小）
7. Shop：商品下架、被其他 GMV Max 占用；App：归因回传断

**有消耗但成本涨、结果掉**
1. 事件回传断：有点击没结果（Pixel 或归因平台没数据）
2. 素材疲劳：CTR 比 30 天均值降 20% 以上，频次升，同一素材跑超过 2 周
3. 人群饱和：CPM 升、触达不再增长
4. 竞争或季节：CPM 高于行业基准，CTR 没变
5. 目标或出价过高导致量缩：消耗降而成本升
6. 落地页或商品问题：点击多，加购和购买都没有

**想加量**
1. 学习期没过（开启不到 7 天或结果不到 50 次）：先不动
2. 过了且成本稳定：加预算，单次不超过 30%，两次隔 2 天
3. 预算加了量不涨：新建广告组扩人群或加素材，不改老的
4. 到了卡片"下一步触发"的数：升级产品（切深层事件、VBO、Smart+），按卡片那一节

## 第 3 步 一个动作

一次只改一个变量。花钱动作（加预算、改出价、开启）改之前一句确认；换素材、暂停单条 ad、新建暂停的广告组不用。

| 动作 | 工具 | 规则 |
|---|---|---|
| 加预算 | adgroup_budget_update；Shop 用 campaign_gmv_max_update；Smart+ 用 smart_plus_adgroup_budget_update | 先读回当前值，单次 ≤ 30%，隔 2 天 |
| 换素材 | 新 ad 用 ad_create；疲劳的用 ad_status_update 暂停 | 新的先开再停旧的 |
| 改出价或目标回报 | adgroup_update；GMV Max 用 campaign_gmv_max_update 改 roas_bid | 只在首因是它时改，一次一档 |
| 扩人群或切产品 | 新建广告组，参数见对应的 ads-products 文件 | 不改在跑的 |
| 申诉 | adgroup_appeal、smart_plus_ad_appeal | 被拒先读原因，能修先修 |
| 充值 | 没有工具，给 Ads Manager 路径 | |

## 第 4 步 确认和复查

读回改动，一句话说改了什么、什么时候看结果、这期间别动什么（学习期 7 天不改目标和人群）。约定复查："3 天后你说一声，我再拉一次对比。"同一提醒只说一次。

## 不做

一天内预算翻倍；同时改两个变量；学习期换目标或事件；ROAS 一掉就关停；没确认就开启或加预算；帮绕审核。卡片各自的"不做"也适用。

## 各卡的差别

通用顺序在上面；每张卡"运营"一节写了它特有的首因顺序和工具，诊断时先按卡的，再按通用的。
