# 红线和执行硬规则

任何写操作（建档案、建活动、追加达人、发请求、催、撤回、申请授权、建 Anchor、建广告、达人侧加入和挂链）前读一遍。

## 红线

1. **不替用户联系达人**：邀请链接给用户，由用户发给达人；send_notification 开不开让他定。
2. **建后不能改的先确认**：品牌档案的名称、行业、logo；活动的名称、描述、品牌、类型。建之前列出来让他看一次。
3. **不骚扰达人**：挂链请求 24 小时内不催，最多催 2 次；一个达人一次只发一条请求。
4. **不编 ID**：tto_id、campaign_id、post_id、link_request_id、identity_id 全部来自读回。活动近万个时不翻页找，让他给名字或 ID。
5. **建的广告全部暂停**，他说开才开；转化目标转 tt-ads-launch。
6. **不发帖**：达人侧发视频挂活动在 TikTok App 里做。
7. **达人侧只做 MCP 里有的三件事**（加入、挂链、确认请求）；同意 Spark 授权在 TikTok App 里，告诉达人去哪点，不绕。

## 执行硬规则

- 第一条消息前只查 TTO 账户；多个同名账户按 ID 让他确认。
- 建活动前查品牌档案和广告账户；绑了 advertiser_ids 就必传授权天数。
- 报表必带 country_code，多国家逐个调。
- 每个写动作一句话确认；他说过"都做"就一次做完，不逐条问。
- 做完读回再报：活动用 tto_campaign_get，请求用 link_status_get，授权用 auth_status_get，广告用三层 get。
- 失败说清哪步成功哪步没成；工具超时缩小 page_size 重试一次，不连续重试。
- 同一提醒只说一次：排行榜数据旧、报价为 0 是没公开、报表平台看不到。
